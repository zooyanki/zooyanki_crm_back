# ADR 0001. Стек бэкенда — NestJS, PostgreSQL, BullMQ

Дата: 2026-09-11. Статус: принято.

## Контекст

Нужен бэкенд для мультимаркетплейс CRM. Рассматривались Python (FastAPI +
Celery), TypeScript (NestJS + BullMQ) и PHP (Laravel).

## Решение

TypeScript: NestJS, PostgreSQL с Prisma, BullMQ поверх Redis.

Причины:

- Фронтенд на Next.js — единый язык на весь проект, общие типы, один набор
  инструментов и одна кадровая база.
- Модульная система NestJS с внедрением зависимостей ложится на паттерн
  адаптеров площадок почти буквально: канал — это модуль, реализующий
  набор интерфейсов.
- Площадки публикуют OpenAPI, а в экосистеме TypeScript генерация
  типизированных клиентов (`openapi-typescript` + `openapi-fetch`) даёт
  проверку типов на границе интеграции без ручной работы.
- `@nestjs/swagger` генерирует схему нашего API, из которой фронт получает
  типы — это закрывает главный риск разделённых репозиториев.

## Последствия

- Разбор и генерация XML для автозагрузки Авито на Node менее удобны,
  чем в Python. Принимаем; библиотеки `fast-xml-parser` и `xmlbuilder2`
  задачу закрывают.
- Тяжёлой аналитики на стороне приложения не будет — агрегаты считаем
  в PostgreSQL.

## Альтернативы

**FastAPI + Celery** — привычнее для интеграций и работы с XML, но добавляет
второй язык и второй инструментарий, а выгода не перевешивает.

**Laravel** — отвергнут: нет опыта и нет преимуществ под эту задачу.
