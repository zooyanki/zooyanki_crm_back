# ADR 0002. Два репозитория: бэкенд и фронтенд раздельно

Дата: 2026-09-11. Статус: принято.

## Контекст

Рассматривались монорепозиторий (`apps/backend` + `apps/web`) и два
отдельных репозитория.

## Решение

Два репозитория:

- `zooyanki_crm_back` — бэкенд, схема БД, миграции, воркеры, адаптеры площадок
- `zooyanki_crm` — фронтенд на Next.js

## Последствия

Главный риск разделения — расхождение контрактов API между фронтом и бэком.
Он закрывается генерацией: NestJS отдаёт OpenAPI-схему через `@nestjs/swagger`,
фронт при сборке прогоняет `openapi-typescript` и получает типы. DTO руками
на фронте не пишутся — это правило зафиксировано в `AGENTS.md` веб-репозитория.

Второй эффект: общая документация не дублируется. Планы, архитектура и ADR
живут только в бэкенд-репозитории, `AGENTS.md` фронта на них ссылается.

Третий: деплой раздельный, версии не связаны. Изменения API должны быть
обратно совместимы либо выкатываться в порядке «бэкенд, затем фронт».
