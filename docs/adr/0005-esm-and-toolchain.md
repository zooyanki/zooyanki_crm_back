# ADR 0005. Проект собирается как ESM

Дата: 2026-09-11. Статус: принято.

## Контекст

При поднятии скелета выяснилось, что актуальные версии инструментов
требуют определённых решений, и выбора между ними практически нет:

- **NestJS 12** поставляется только как ESM: в `@nestjs/common`
  задан `"type": "module"` и CommonJS-сборки в пакете нет.
- **NestJS 12** требует **TypeScript 6 и выше** (`@nestjs/schematics`
  объявляет peer `typescript >= 6.0.0`).
- **Prisma 7** убрал поле `url` из блока `datasource` и требует
  driver adapter при создании клиента.

## Решение

Проект — ESM: в `package.json` стоит `"type": "module"`,
в `tsconfig.json` — `module` и `moduleResolution` в значении `nodenext`.

TypeScript зафиксирован на версии 6. Переход на TypeScript 7 отложен:
`openapi-typescript` пока объявляет peer `^5.x`, а декораторы и
`emitDecoratorMetadata`, на которых держится NestJS, в нативном
компиляторе ещё не обкатаны.

Prisma: строка подключения задана в `prisma.config.ts` для CLI и
в `PrismaPg` при создании клиента; генератор — `prisma-client`
с `moduleFormat = "esm"` и выводом в `src/generated/prisma`.

## Последствия

- **Относительные импорты обязаны заканчиваться на `.js`**, даже когда
  указывают на файл `.ts`. Это главное, обо что спотыкаются при правках.
- Пакеты, отдающие только CommonJS, импортируются через default-импорт;
  при проблемах с именованными импортами проверяй формат пакета.
- В `package.json` есть `overrides` для `openapi-typescript`: его peer-диапазон
  на TypeScript устарел и без переопределения ломает любую установку
  зависимостей.
