# Модель данных

Все доменные таблицы содержат `tenant_id` и закрыты политиками RLS.
Источник истины — Prisma-схема в `prisma/schema.prisma`; этот документ
описывает замысел, а не является формальным описанием.

## Арендаторы и доступ

- `tenants` — арендатор
- `users` — пользователь системы
- `memberships` — связь пользователя с арендатором и его роль

## Подключённые аккаунты площадок

`channel_accounts` — центральная таблица интеграций:

| Поле | Смысл |
|---|---|
| `tenant_id` | владелец |
| `channel` | `avito`, `ozon`, `wb`, `drom` |
| `auth_type` | `client_credentials` или `authorization_code` |
| `credentials_encrypted` | зашифрованные `client_id`/`client_secret` |
| `external_user_id` | `user_id` из `/core/v1/accounts/self` |
| `scopes` | выданные скоупы |
| `status` | `active`, `invalid_credentials`, `disabled` |

Дискриминатор `auth_type` — точка расширения на мультиаккаунтность:
переход к обслуживанию клиентских аккаунтов не потребует миграции схемы.

`oauth_tokens` — `access_token`, `refresh_token`, `expires_at`. У Авито токен
живёт час, поэтому горячий кеш ещё и в Redis.

## Каталог

- `products` — товар
- `variants` — конкретная продаваемая позиция со своим SKU

`channel_listings` — связь варианта с публикацией на площадке:

| Поле | Смысл |
|---|---|
| `variant_id` | наш вариант |
| `channel_account_id` | где опубликовано |
| `external_id` | идентификатор на площадке |
| `avito_ad_id` | наш идентификатор в XML-фиде автозагрузки |
| `avito_item_id` | идентификатор объявления в Авито |
| `status` | состояние публикации |
| `last_error` | ошибка последней выгрузки |

Три идентификатора у Авито — не избыточность: фид оперирует `ad_id`,
REST оперирует `item_id`, а `/autoload/v2/items/avito_ids` их связывает.

## Склад

- `inventory_items` — остаток по варианту и складу, источник истины
- `stock_movements` — журнал движений: приход, расход, резерв, корректировка

Изменение остатка в одной транзакции пишет движение и кладёт в `outbox`
команду публикации во все активные каналы этого варианта.

## Заказы

- `orders` — `status` в нашей номенклатуре, `raw_status` как пришёл
  от площадки, `external_id`, `channel_account_id`, суммы, покупатель, доставка
- `order_items` — позиции, со ссылкой на `variant_id` где удалось сопоставить
- `order_status_map` — таблица соответствия статусов площадок нашим

Маппинг статусов живёт данными, а не условными операторами в коде: у Авито
`applyTransition`, у Ozon и WB свои машины состояний.

## Переписка и отзывы

- `conversations`, `messages` — канонические диалоги
- `reviews`, `review_answers` — отзывы и ответы

## Аналитика

`stats_daily` — срез по дню, варианту и каналу: показы, контакты, избранное,
расходы на продвижение. Заполняется ночной джобой, служит источником отчётов.

## Служебные таблицы

- `outbox` — исходящие команды: тип, полезная нагрузка, idempotency-ключ,
  число попыток, статус
- `sync_states` — курсоры синхронизации по каналу и типу сущности
- `api_call_log` — журнал вызовов к площадкам с вырезанными секретами
