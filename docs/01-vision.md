# Видение продукта

## Цель

Один инструмент для управления продажами сразу на нескольких торговых площадках.
Продавец ведёт каталог, склад, заказы и переписку в одном месте, а система
раскладывает это по площадкам и собирает обратно.

## Площадки

| Площадка | Статус | Примечание |
|---|---|---|
| Avito | в работе | первая интеграция, задаёт форму адаптера |
| Ozon | план | Seller API, богатый REST |
| Wildberries | план | Suppliers API |
| Drom | план | API беднее, часть возможностей будет недоступна |

Авито выбран первым сознательно: у него самый неудобный набор ограничений
(публикация только через XML-фид, вебхуки лишь у мессенджера, индивидуальные
лимиты на каждый метод). Если адаптер выдержит Авито, остальные площадки лягут
в ту же абстракцию без боли.

## Что система должна уметь

1. **Единый каталог.** Товар и его варианты живут у нас, публикации на площадках —
   производные от него.
2. **Собственный склад.** Остатки ведутся в CRM, она источник истины.
   Изменение остатка автоматически разъезжается по всем активным площадкам.
3. **Единая витрина заказов.** Заказы всех площадок в одном списке
   с нормализованными статусами.
4. **Единое окно переписки.** Диалоги с покупателями со всех площадок.
5. **Сквозная аналитика.** Показы, контакты, продажи и расходы на продвижение
   в одном отчёте, сопоставимые между площадками.

## Границы

Вне области на обозримое будущее: бухгалтерия и документооборот, собственная
логистика и курьеры, маркетплейс-агностичный ценовой репрайсер, мобильное
приложение.

## Мультиарендность

Сейчас система обслуживает один аккаунт Авито. Но схема данных и авторизация
с самого начала спроектированы под несколько арендаторов и несколько
подключённых аккаунтов на арендатора — переключение на этот режим не должно
требовать миграции данных. См. `docs/adr/0003-tenancy-rls.md`.
